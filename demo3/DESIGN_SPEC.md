# Demo 3 设计方案：暗色增长塔台 Signal Control Room

## 1. 文档目的

本文档定义 YeahPromos Merchant 首页第三套视觉与框架方案，供后续高保真 Demo、组件拆分和正式前端迁移使用。

该方案保留产品框架中的任务域、业务功能、数据状态与权限边界，但在视觉语言、内容层级和数据表达方式上与 Demo 2 的明亮湖蓝 Bento 驾驶舱形成明显差异。

本文档只定义设计，不代表所有后台接口和业务规则已经实现。

## 2. 方案定位

### 2.1 核心概念

将商家首页设计成一个“联盟营销增长塔台”。用户进入页面后，不是先浏览一组孤立指标，而是按以下顺序完成判断：

1. 当前品牌和数据是否正常；
2. 业务走势是否偏离预期；
3. 今天最需要处理的事项是什么；
4. 哪些伙伴、活动或数据变化造成了结果；
5. 下一步应该进入哪个业务队列。

### 2.2 页面受众

- Organization Owner
- Brand Admin
- Partnership Manager
- Campaign Manager
- Analyst
- Finance

不同角色看到相同的页面骨架，但任务、财务数据、危险操作和敏感信息根据权限变化。

### 2.3 页面唯一任务

帮助商家在 30 秒内判断业务状态，并进入优先级最高的操作队列。

## 3. 与 Demo 2 的差异

| 维度 | Demo 2：卡片化运营驾驶舱 | Demo 3：暗色增长塔台 |
|---|---|---|
| 整体气质 | 明亮、柔和、平静 | 深色、精密、实时、控制中心感 |
| 页面结构 | 不规则 Bento 卡片 | 横向业务飞行条 + 主信号轨迹 + 纵向决策队列 |
| 数据组件 | 独立指标卡和小柱图 | 连续信号条、刻度、轨迹线和变化原因 |
| 任务表达 | 多张并列任务卡 | 按影响和紧急度排序的纵向任务轨道 |
| 伙伴表现 | 白色排行卡 | 类似圈速榜的动能排行 |
| 圆角语言 | 大圆角、柔软 | 中小圆角、机械面板、嵌套边框 |
| 主色 | 湖蓝 `#168C9B` | 冰蓝 `#66D4E8` + 琥珀 `#F0A64A` |
| 信息密度 | 中等、留白明显 | 中高密度，但通过轨道和刻度维持秩序 |

## 4. 产品框架映射

Demo 3 的侧边栏遵循 `docs/01-information-architecture.md` 中的任务域，不使用旧产品按内部模块堆叠的导航方式。

| 任务域 | Demo 3 导航名称 | 首页对应信号 |
|---|---|---|
| 总览与待办 | Command overview | 业务飞行条、决策队列、近期活动 |
| 招募与伙伴 | Partner operations | 待审核申请、邀请、伙伴动能排行 |
| 活动 | Campaign control | 活动完整度、发布倒计时、运行状态 |
| 商品与推广资产 | Product & assets | Feed 同步、商品异常、优惠券和素材状态 |
| 佣金与规则 | Commission logic | 佣金趋势、规则冲突和待生效规则 |
| 数据与交易 | Data & transactions | 销售轨迹、异常交易、审批和导出 |
| 财务 | Finance | 余额覆盖天数、充值、付款和发票 |
| 消息与通知 | Communications | 待回复消息、系统通知和发送状态 |
| 集成与设置 | Systems & access | 店铺连接、同步、团队权限和 API 状态 |

侧边栏名称可以使用简洁英文，但页面路由、数据合同和权限范围必须与产品框架保持一致。

### 5.2 页面宽度

- 侧边栏：`232px`；
- 主内容最大宽度：`1540px`；
- 主内容左右留白：桌面端 `36–48px`；

- 页面不使用顶部主导航，顶部只承担工作区上下文和工具操作。

## 6. 核心区域设计

### 6.1 侧边栏 Command Rail

侧边栏是一个持续可见的任务域控制轨道。

#### 内容

- YeahPromos 品牌标识；
- 当前组织、品牌和站点；
- 九个任务域入口；
- 待处理数量、异常符号和未读数量；
- 帮助、设置、账号和当前角色；
- 集成健康状态和最近同步时间。

#### 视觉

- 使用深海军蓝背景；
- 当前页面使用左侧冰蓝信号线、浅色文字和轻微内发光；
- 不使用整块高饱和蓝色菜单背景；
- 子菜单使用缩进轨道和小节点；
- 异常状态显示文字或符号，不只依赖红色。

#### 交互

- 一级菜单点击后展开或收起子菜单；
- 切换任务域时主内容淡出并向上移动 `6px`，新内容进入；
- 移动端侧边栏变为全屏抽屉；
- 抽屉关闭按钮需要明确文本或辅助技术标签。

### 6.2 顶部工作区 Context Bar

Context Bar 不承担主导航，只表达全局数据范围。

#### 内容

- 当前品牌：Northstar Labs；
- 当前站点：US Store；
- 日期范围；
- 币种与时区；
- 数据更新时间；
- 同步状态；
- 通知、下载中心和账号菜单。

#### 状态文案示例

- `All systems synced · 4 min ago`
- `3 feed records need attention`
- `Report export is ready`
- `Viewing Northstar Labs · USD · America/Los_Angeles`

### 6.3 Business Flight Strip

Business Flight Strip 是 Demo 3 的标志性组件，也是整套设计唯一最强的视觉记忆点。

它将多个经营指标串成一条连续业务信号，不使用七张相互独立的 KPI 卡。

```text
GROSS SALES        ORDERS          CONVERSION        COMMISSION       BALANCE COVER
$186,420.80        1,284           2.6%              $24,860.40       6 DAYS
▲ 15.2%            ▲ 8.4%          ▲ 0.3%            ▲ 9.6%           ATTENTION
```

#### 指标范围

- Clicks
- Orders
- Gross Sales
- Net Sales
- Commission
- Conversion
- Total Payout
- Balance Cover，可作为运营状态而非传统 KPI

#### 表达规则

- 每个指标显示名称、当前值、对比变化和迷你趋势；
- 正向变化使用绿色，风险使用琥珀或红色；
- 数字必须使用等宽数字特性；
- 鼠标悬停显示指标定义、对比区间和更新时间；
- 点击后进入带预设指标和时间范围的绩效页面；
- Balance Cover 点击后进入财务的余额与付款页面。

### 6.4 主业务信号轨迹 Revenue Trajectory

主信号轨迹替代传统“大折线图 + 一堆没有解释的 KPI”。

#### 内容

- 当前主指标曲线；
- 前一周期对比线；
- 活动、商品同步、伙伴增长等事件节点；
- 当前指标定义、时间粒度、币种和更新时间；
- 图表旁的变化原因说明。

#### 原因说明示例

- Northstar Media 本周贡献提高 `18.4%`；
- Summer Sale 进入预热期，活动链接点击增加；
- 三个商品同步失败，影响伙伴可推广商品数量；
- 28 笔交易尚未审批，佣金仍处于 Pending 状态。

#### 交互

- 可切换 Sales、Orders、Commission 和 Clicks；
- 点击事件节点打开对应伙伴、活动或错误详情；
- 图表必须提供可访问的数据表替代；
- 无数据时解释数据为什么不存在并给出下一步。

### 6.5 今日决策队列 Decision Queue

决策队列使用纵向轨道，不使用四张相同尺寸的任务卡。

#### 排序规则

任务优先级由以下因素共同决定：

1. 是否阻塞付款、活动或数据同步；
2. 是否存在安全、权限或财务风险；
3. 对销售、伙伴和活动的影响范围；
4. 截止时间；
5. 是否需要当前用户角色处理。

#### 任务结构

```text
PRIORITY 01 · FINANCE
Balance covers six payout days
Current balance may not cover the next payout run.
[Review balance  ↗]
```

每个任务必须包含：

- 优先级；
- 任务域；
- 标题；
- 原因；
- 业务影响；
- 截止时间或状态；
- 明确动作；
- 权限受限时的申请路径。

#### 默认演示任务

1. 余额只能覆盖六天付款；
2. 三个商品 Feed 同步失败；
3. 28 笔交易等待审批；
4. 12 个伙伴申请等待审核；
5. Summer Sale 五天后开始但配置未完成。

### 6.6 伙伴动能排行 Partner Momentum

伙伴排行采用“圈速榜”式横向信号条，不使用传统数据表。

```text
01  Northstar Media  ███████████████  $6,845.20  +18.4%
02  The Dealroom     ███████████      $5,126.80  +12.1%
03  Shopper Edit     █████████        $4,382.10   +7.8%
```

#### 每行信息

- 当前排名和上期排名变化；
- 伙伴名称和类型；
- 收入或佣金贡献；
- 订单、转化或点击辅助指标；
- 趋势；
- 当前关系状态。

#### 交互

- 点击行打开伙伴详情抽屉；
- 指标切换时排行条重新计算；
- 详情抽屉保留伙伴画像、合作状态、佣金、趋势和联系历史；
- 数据不足时明确标注，不用 `0` 冒充缺失数据。

### 6.7 活动轨道 Campaign Track

活动按生命周期和配置完整度展示：

- Draft
- Scheduled
- Active
- Paused
- Completed
- Archived

配置不完整不能伪装成生命周期状态，应单独显示 `Completeness`。

默认示例：

- Summer Sale：Scheduled，完整度 `82%`，五天后开始；
- Northstar Partner Program：Active，48 个活跃伙伴；
- Creator Launch：Draft，缺少佣金规则和推广素材。

### 6.8 风险雷达 Risk Radar

风险按领域分组，而不是平铺多个红色卡片。

#### 风险类型

- 财务余额；
- Feed 或集成同步；
- 异常交易；
- 活动依赖缺失；
- 佣金规则冲突；
- 权限或 API 凭证风险；
- 导出、发票等长任务失败。

每个风险显示原因、更新时间、影响范围和恢复动作。

### 6.9 快捷指令 Quick Commands

快捷操作使用紧凑指令面板：

- Invite partner
- Create campaign
- Add product
- Add coupon
- Export report

主动作使用琥珀色实心按钮，普通动作使用冰蓝描边。带箭头的按钮使用“按钮内圆形图标岛”结构，不能把箭头裸露放在文字旁。

| `--panel-raised` | `#15313C` | 抬升面板和悬停层 |
| `--panel-deep` | `#0A1A22` | 图表和轨道内部背景 |
| `--text-primary` | `#EAF5F5` | 主文字 |
| `--text-secondary` | `#9DB3B8` | 次要文字 |
| `--text-muted` | `#668087` | 注释和弱标签 |
| `--signal` | `#66D4E8` | 主信号、选中和关键数据 |

| `--hairline` | `rgba(137, 199, 206, 0.16)` | 机械面板细线 |

### 7.2 色彩约束

- 红色只用于高风险或失败，不用于普通提醒；
- 琥珀色用于需要行动但尚未失败的事项；
- 绿色不代表所有上涨，上涨指标仍需判断业务含义；
- 状态必须同时有文字、符号或图标；
- 大面积区域避免纯黑和高饱和渐变。

### 7.3 字体

使用仓库 `fonts` 目录中的 Plus Jakarta Sans：

- 页面标题：700 或 800；
- 区域标题：600 或 700；
- 正文：400 或 500；
- 数据：600 或 700，并启用 `font-variant-numeric: tabular-nums`；
- 微型标签：700，增加字距并使用大写；
- 不引入在线字体。

### 7.4 字号建议

| 角色 | 桌面字号 |
|---|---|
| 页面标题 | `30–36px` |
| 核心轨迹值 | `28–34px` |
| 模块标题 | `18–22px` |
| 卡片标题 | `13–15px` |
| 正文 | `11–13px` |
| 标签和状态 | `9–11px` |

### 7.5 圆角和嵌套面板

- 主面板外壳：`18–22px`；
- 内层核心面板：外壳圆角减 `4–6px`；
- 控件：`10–12px`；
- 状态胶囊：全圆角；
- 不使用所有组件统一 `24px` 大圆角；
- 主要面板使用 Double Bezel：外层托盘 + 内层内容核心。

### 7.6 边框和阴影

- 禁止普通灰色 `1px solid` 边框；
- 使用蓝绿色半透明 hairline；
- 面板以亮部内描边、背景层级和轻微环境阴影表现深度；
- 禁止黑色重阴影；
- 悬停时只提高亮度、描边强度和轻微位移。

## 8. 数据可视化规范

### 8.1 图表原则

- 只保留支持决策的图表；
- 图表旁必须说明指标定义、单位和更新时间；
- 对比区间必须明确；
- 延迟数据需要提示；
- 图表必须提供数据表替代；
- 不使用无业务意义的仪表盘、雷达图和装饰性波形。

### 8.2 数字格式

- 金额始终带币种；
- 大数可缩写，但悬停显示完整值；
- 百分比保持统一小数位；
- Clicks、Orders 等计数不显示小数；
- 缺失值显示 `—` 并解释原因；
- 数据延迟不能显示为 `0`。

### 8.3 趋势状态

趋势不是只看正负号：

- 销售增长通常为正向；
- Voids 增长为风险；
- Total Payout 增长需要结合销售增长解释；
- Pending Transactions 增长代表任务压力；
- Balance Cover 下降需要触发提醒。

## 9. 状态与权限

Demo 3 必须可以展示以下横切状态。

### 9.1 正常状态

- 所有数据可用；
- 同步健康；
- 用户具有相应操作权限；
- 所有按钮可进入对应模块或演示占位页。

### 9.2 空状态

至少区分：

- 新账号没有业务数据；
- 当前筛选没有结果；
- 集成尚未完成；
- 数据尚在首次同步。

空状态需要给出明确下一步，例如连接店铺、邀请伙伴或创建活动。

### 9.3 同步状态

- 局部区域保持可用；
- 显示同步对象、开始时间和当前进度；
- 用户可以离开页面；
- 完成后通过通知更新。

### 9.4 错误状态

- 说明哪个数据源失败；
- 说明哪些区域仍然可用；
- 提供重试、查看记录或联系支持；
- 不使用整页通用错误覆盖全部内容。

### 9.5 权限受限

- 隐藏不可发现的敏感信息；
- 可见但不可操作时，说明需要的角色；
- 财务、交易审批、团队权限和 API 操作需要单独控制；
- 提供联系 Owner 或申请权限路径。

### 9.6 危险操作

批准、拒绝、作废、屏蔽、删除和断开集成必须包含：

- 二次确认；
- 影响范围；
- 原因；
- 操作者；
- 结果和审计提示。

## 10. 交互与动效

### 10.1 页面进入

- Flight Strip 指标从左到右依次出现；
- 主信号轨迹和决策队列分别淡入上移；
- 总时长控制在 `500–800ms`；
- 不为每个小图标添加独立动画。

### 10.2 指标切换

- 旧轨迹降低透明度并移动 `4px`；
- 新轨迹从反方向进入；
- 数字可使用短促的交叉淡入，不使用快速滚动计数器；
- 动画只使用 `transform` 和 `opacity`。

### 10.3 决策队列

- 完成任务后节点产生一次轻微脉冲；
- 任务移入完成区时使用缩小和淡出；
- 后续任务平滑补位；
- 不动画高度，使用 FLIP 或 transform 方案。

### 10.4 按钮

- 悬停时按钮整体上移 `1–2px`；
- 按下缩放至 `0.98`；
- 尾部图标岛轻微向右上移动；
- 使用自定义曲线 `cubic-bezier(0.32, 0.72, 0, 1)`；
- 禁止 `linear` 和 `ease-in-out`。

### 10.5 减少动画

遵循 `prefers-reduced-motion`，关闭进入编排、脉冲和轨迹切换位移，只保留必要的状态变化。

## 11. 响应式规则

### 11.1 大桌面端：`≥ 1280px`
