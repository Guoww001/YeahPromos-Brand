# 方案一设计文档：PartnerBoost 蓝白卡片工作台

> 文档状态：待确认  
> 版本：v1.0  
> 目标页面：YeahPromos Amounts / Overview  
> 设计范围：页面框架、视觉风格、数据展示与 Demo 交互，不改变现有业务功能

## 1. 项目目标

将 YeahPromos 当前以顶部导航为主的 Amounts 页面，重构为更接近 PartnerBoost 后台产品的蓝白卡片工作台。

目标用户是需要快速查看推广结果、佣金状态和新商家的联盟发布者。页面的唯一核心任务是：让用户在进入页面后，能够迅速判断近期表现、佣金进度和可申请商家，并立即进行下一步操作。

本方案只调整前端框架、信息层级、视觉样式和数据呈现方式，不修改以下业务含义：

- Overview、Merchants、Reports、Amazon、Channels、Payments、Accounts、Tools 等原有入口；
- Clicks、Sales、Sale Amount、Approved Commission、CVR、Tasks、Level 等指标；
- Top 5 Advertisers、Commission、Merchants、New Arrivals 等内容模块；
- 日期筛选、商家网址、佣金、地区、Cookie Days、Apply 等现有功能。

## 3. 设计方向

### 3.1 设计关键词

- 清爽
- 可信
- 模块化
- 易扫描
- 轻量运营后台
- PartnerBoost 风格延续

### 3.2 核心视觉原则

1. 使用固定白色侧边栏代替原顶部导航，让主工作区更聚焦数据。
2. 页面背景采用浅灰蓝色，内容使用白色卡片承载。
3. 品牌蓝只用于当前状态、关键按钮和可交互信息，避免整页泛蓝。
4. 用低饱和状态色区分数据类别，不依赖高饱和颜色制造层级。
5. 数值高于标签，标签高于辅助说明，让用户先看到结果，再理解来源。
6. 同类模块使用一致的圆角、边框、间距和操作位置。

### 3.3 方案记忆点

页面的唯一强化视觉元素是顶部“经营状态带”：七个核心指标以柔和的蓝、绿、紫、橙、粉色分组显示，形成与 PartnerBoost 状态卡一致的产品识别。

除状态带以外，其余区域保持白色、浅灰和少量品牌蓝，避免页面显得幼稚或颜色过多。

## 5. 页面尺寸与网格

### 5.1 桌面端基准

- 设计基准宽度：`1440px`；
- 最佳展示宽度：`1440px–1920px`；
- 固定侧边栏宽度：`240px`；
- 主工作区左侧起点：`264px`；
- 主内容左右安全边距：`24px`；
- 主内容最大宽度：`1480px`；
- 页面顶部间距：`24px`；
- 模块纵向间距：`20px`；
- 卡片内部间距：`20px–24px`。

### 5.2 十二列网格

- 页面主体采用十二列网格；
- 列间距为 `20px`；
- Top 5 Advertisers 占七列；
- Commission 与 Merchants 组成的摘要区域占五列；
- New Arrivals 占满十二列；
- 商家卡片在宽屏下每行三张。

### 5.3 间距体系

统一使用以下间距，不在组件中随意增加新的数值：

```text
4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48
```

其中：

- `4px`：图标和极短标签间距；
- `8px`：徽标、标签、按钮内部间距；
- `12px`：同组字段间距；
- `16px`：卡片内部小区块间距；
- `20px`：网格间距；
- `24px`：卡片标准内边距；
- `32px`：大区块之间的视觉分隔。

## 6. 侧边栏设计

### 6.1 外观

- 固定在页面左侧，高度为 `100vh`；
- 背景为纯白色；
- 右上角和右下角圆角为 `20px`；
- 使用非常轻的右侧阴影，与浅灰蓝主背景分离；
- 内容区域可滚动，底部账户区域保持可见。

### 6.2 导航层级

导航顺序保持原系统含义：

1. Overview
2. Merchants
3. Reports
4. Amazon
5. Channels
6. Payments
7. Accounts
8. Tools

Amazon、Reports、Tools 等存在子菜单时，使用向下箭头展开，不跳转到新的顶部导航。

### 6.3 菜单状态

- 默认项：透明背景，深灰文字，线性图标；
- 悬停项：`#F1F7FD` 背景，文字变为品牌蓝；
- 当前项：品牌蓝背景、白色文字，圆角 `9px`；
- 展开父级：保持蓝色当前状态；
- 子菜单：左侧使用淡蓝圆点或细竖线建立层级。

### 6.4 底部区域

侧边栏底部依次放置：

- Help；
- Settings；
- 当前用户头像、用户名和下拉入口。

原页面顶部的 `Guowv` 用户按钮迁移至此处，不再独占顶部空间。

## 8. 核心经营状态带

### 8.1 指标顺序

1. Clicks
2. Sales
3. Sale Amount
4. Approved Commission
5. CVR
6. Tasks
7. Level

### 8.2 卡片结构

每张指标卡由四部分组成：

- 左上角：指标名称；
- 右上角：对应线性图标或字母标识；
- 中部：核心数值；
- 底部：与上一周期对比或简短状态。

示例：

```text
CLICKS                       ↗
12,846
+8.4% vs previous period
```

### 8.3 颜色分组

| 指标 | 色彩倾向 | 用途 |
| --- | --- | --- |
| Clicks、CVR | 淡蓝 | 流量与转化效率 |
| Sales | 淡青绿 | 已发生的转化 |
| Sale Amount、Approved Commission | 淡绿色 | 金额与收益 |
| Tasks | 淡橙色 | 待处理事项 |
| Level | 淡紫色 | 账户等级与身份 |

卡片不使用高饱和纯色大面积填充。背景色透明度保持轻柔，数值统一使用深色，确保可读性。

### 8.4 数值规则

- 金额统一显示货币符号和千位分隔符，例如 `$12,480.50`；
- 比例统一保留一位小数，例如 `2.4%`；
- Clicks、Sales、Tasks 使用整数；
- Level 使用单个等级字母和等级说明；
- 实际值为零时显示 `0` 或 `$0.00`；
- 数据缺失时显示 `—`，不能把缺失数据误写成零；
- 所有数字启用等宽数字特性：`font-variant-numeric: tabular-nums`。

Demo 阶段可使用非零模拟数据展示信息层级，同时必须保留一套零数据状态用于验证。

## 9. Top 5 Advertisers 模块

### 9.1 卡片结构

- 标题：`Top Advertisers`；
- 副标题：`Tracked commission · Last 30 days`；
- 右上角操作：`View report`；
- 主体：五条横向排名条；
- 每条包含排名、商家名称、进度条、佣金金额和趋势。

### 9.2 数据表达

- 进度条长度按最高佣金值归一化；
- 第一名使用品牌蓝，第二至第五名使用不同明度的浅蓝；
- 金额右对齐；
- 趋势信息只显示颜色和百分比，不增加复杂图标；
- 没有数据时显示带行动建议的空状态，而不是五条无意义的灰线。

空状态文案示例：

```text
No tracked commission yet
Start promoting a merchant to see rankings here.
```

## 10. Commission 与 Merchants 摘要

右侧区域由两张等宽卡片组成，在桌面宽屏下并排，在中等宽度下上下排列。

### 10.1 Commission

展示：

- Approved；
- Pending；
- Total Paid。

使用三段式环形图或横向占比条，旁边显示金额。Approved 使用绿色，Pending 使用橙色，Total Paid 使用品牌蓝。

### 10.2 Merchants

展示：

- Joined；
- Pending；
- Rejected。

使用三个紧凑状态行，每一行包含状态圆点、名称、数值和轻量进度条。Rejected 只使用低饱和粉色，不使用警报红。

### 10.3 交互

点击 Commission 状态跳转至对应支付或佣金列表；点击 Merchants 状态跳转至对应商家筛选结果。Demo 阶段可用 Toast 或状态切换模拟跳转结果。

### 12.2 内容顺序

## 13. 视觉规范

### 13.1 颜色 Token

```css
--color-brand: #3297E9;
--color-brand-hover: #2387D8;
--color-brand-soft: #EAF5FE;
--color-canvas: #F4F7FB;
--color-surface: #FFFFFF;
--color-text: #1E2936;
--color-text-muted: #718096;
--color-border: #E4EBF3;
--color-success-soft: #E2F7EA;
--color-warning-soft: #FFF0E3;
--color-purple-soft: #F0EAFE;
--color-danger-soft: #FCE8EC;
```

颜色语义必须固定。品牌蓝不能同时表示错误或警告，粉色不能用于普通主按钮。

### 13.2 字体

- 英文标题、正文与数字：项目 `fonts` 目录中的 `Plus Jakarta Sans`；
- 可用字重：`400`、`500`、`600`、`700`、`800`；
- 中文：`PingFang SC`、`Microsoft YaHei`、`Noto Sans SC`；
- 系统兜底：`sans-serif`。

Demo 必须通过 `@font-face` 加载本地 WOFF2 字体，不接入在线字体。由于当前字体文件只包含 Latin 字符，中文自动回退到本地中文字体，不能因为字体切换造成布局跳动。

### 13.3 字号层级

| 用途 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 页面主标题 | `28 / 36px` | 700 |
| 模块标题 | `18 / 26px` | 700 |
| KPI 数值 | `26 / 32px` | 700 |
| 卡片主信息 | `15 / 22px` | 600 |
| 正文 | `14 / 22px` | 400 |
| 标签与辅助信息 | `12 / 18px` | 500–600 |

正文默认左对齐；表格数值和金额默认右对齐；短状态值可以居中。

### 13.4 圆角

```css
--radius-card: 14px;
--radius-control: 9px;
--radius-chip: 999px;
--radius-sidebar: 20px;
```

### 13.5 阴影

```css
--shadow-sidebar: 8px 0 28px rgba(38, 72, 101, 0.06);
--shadow-card: 0 8px 24px rgba(42, 72, 102, 0.06);
--shadow-card-hover: 0 14px 30px rgba(42, 72, 102, 0.10);
```

阴影只用于侧边栏、主卡片和浮层。筛选器、徽标、表格行不使用阴影。

### 13.6 图标

- 使用统一的线性图标库；
- 默认描边宽度保持一致；
- 导航图标为 `18px`；
- 工具按钮图标为 `18–20px`；
- KPI 图标为 `18px`；
- 不混用线性、实心和拟物图标。

## 15. 动效规范

动效服务于状态变化，不承担装饰任务。

- 页面首次加载：状态卡按 `40ms` 间隔淡入；
- 卡片悬停：`180ms` 上移和阴影变化；
- 抽屉打开：`240ms` 从右侧滑入；
- 按钮状态：`160ms` 颜色过渡；
- 图表：首次进入时执行一次 `400ms` 数值增长；
- 不循环播放动画；
- 当系统启用 `prefers-reduced-motion` 时关闭位移和数字增长动画。

## 16. 响应式规则

### 大屏：`≥ 1440px`

- 侧边栏宽度 `240px`；
- KPI 七列显示；
- Top 5 Advertisers 与摘要区按七列、五列分配；
- New Arrivals 三列。

### 中屏：`1200–1439px`

- 侧边栏宽度缩小至 `220px`；
- KPI 调整为四列加三列；
- Top 5 Advertisers 与摘要区保持左右布局；
- New Arrivals 两列。

### 平板：`768–1199px`

- 侧边栏折叠为 `72px` 图标栏；
- 悬停或点击图标显示菜单名称；
- KPI 三列或两列；
- 排行和摘要区上下排列；
- New Arrivals 两列。

### 移动端：`< 768px`

- 侧边导航改为左侧抽屉，仍然是侧边栏逻辑，不恢复顶部横向导航；
- 页面顶部显示菜单按钮、标题和用户头像；
- KPI 两列，金额类指标可占满一行；
- 所有分析模块单列显示；
- New Arrivals 单列；
- 商家详情抽屉全屏显示。

## 17. 无障碍要求

- 正文和背景对比度至少达到 WCAG AA；
- 不只依赖颜色表达状态，必须同时提供文字或图标；
- 所有按钮、筛选器、菜单和商家卡片支持键盘操作；
- 焦点样式使用 `2px` 品牌蓝描边和 `2px` 外间距；
- 图标按钮必须提供可读的 `aria-label`；
- 抽屉打开后焦点进入抽屉，关闭后返回触发元素；
- 图表同时提供文本数值，不能只通过图形传达数据。

Demo 阶段不实现：

- 真实登录和权限；
- 真实支付流程；
- 后端 API；
- 实际商家申请提交；
- 复杂图表分析；
- 完整路由页面。

## 19. 推荐组件拆分

为了后续迁移到 Vue，原生 HTML/CSS/JS Demo 也应按以下组件边界组织：

```text
AppShell
├─ SideNavigation
│  ├─ BrandLogo
│  ├─ NavigationGroup
│  ├─ NavigationItem
│  └─ UserMenu
├─ PageHeader
│  ├─ Breadcrumb
│  ├─ DateRangePicker
│  └─ UtilityActions
├─ MetricsStrip
│  └─ MetricCard × 7
├─ AdvertiserRankingCard
├─ CommissionSummaryCard
├─ MerchantStatusCard
├─ NewArrivalsSection
│  └─ MerchantCard × N
├─ MerchantDetailDrawer
└─ ToastMessage
```

Demo 数据应集中在单独的数据文件中，通过数组渲染指标、导航和商家，避免在 HTML 中复制大量结构。

建议数据对象：

```js
const dashboardData = {
  period: {},
  metrics: [],
  advertisers: [],
  commission: {},
  merchantStatus: {},
  newArrivals: []
};
```

迁移 Vue 时只需要把各模块转换为 `.vue` 组件，并把集中数据替换为接口或 Store 数据，不需要重新设计 DOM 层级。

## 20. 设计验收标准

### 框架

- [ ] 原顶部导航已完全迁移到侧边栏；
- [ ] 桌面端、平板端、移动端都保持侧边导航逻辑；

- [ ] 主内容在 `1366px` 宽度下不产生横向滚动。

- [ ] 页面背景、卡片、侧边栏层级清晰；
- [ ] 当前菜单使用统一品牌蓝；
- [ ] 五色状态带颜色柔和且文字对比清晰；
- [ ] 圆角、阴影和间距符合 Token；
- [ ] 不包含参考截图中的红色教程标注；
- [ ] 页面没有使用与设计无关的渐变、玻璃拟态或大面积深色区域。

- [ ] 金额、百分比、整数格式统一；
- [ ] 零值和缺失值能够明确区分；

### 交互

- [ ] 侧边栏、筛选器、卡片和抽屉有明确的悬停、焦点和激活状态；

## 21. 最终效果预期

页面应当让熟悉 PartnerBoost 的用户感到结构和交互语言一致，同时仍然保留 YeahPromos 的业务名称和功能。

最终效果不是简单复制 PartnerBoost，也不是把原页面换成蓝色，而是将其最有价值的后台设计方法迁移过来：固定侧边导航、浅色工作区、状态色数据卡、模块化内容卡片和右侧详情抽屉。
