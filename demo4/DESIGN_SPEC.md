# Demo 4 设计方案：Brand Pulse 品牌增长编辑台

## 1. 方案定位

这不是上一版暗色运营驾驶舱的浅色翻版，而是一套更接近国际品牌编辑部、增长团队与数据产品交汇处的视觉系统。

核心命题：**让联盟营销后台看起来像一个正在持续产出增长结论的品牌工作台，而不是一组被动陈列的报表。**

- 页面用途：供品牌方查看增长表现、处理伙伴与活动任务、管理数据和财务状态。
- 主要用户：Brand Admin、Campaign Manager、Partner Manager、Finance Operator。
- 主要任务：用户进入页面后，应在 10 秒内知道“增长是否健康、哪里出现变化、下一步该做什么”。
- 实现边界：后续 Demo 使用原生 HTML、CSS、JavaScript，保留侧边栏导航及全部示例页面，不接真实 API。

## 2. 参考主题提炼

参考 Media Kit 的视觉语言包括：

1. 黑白高反差的文字结构，标题粗重、直白、有传播力。
2. 洋红、玫红、珊瑚红与深酒红组成的高饱和品牌色带。
3. 大字号数字、粗线图标和分组式信息块，强调成果而非装饰。
4. 由黑色向洋红扩散的光晕，表现“增长被激活”的动态感。
5. 横向排布、明显分区与大留白并存，适合品牌叙事和数据表达。

本方案不照搬 PDF 的暗色背景、厚重卡片和宣传册构图，而是进行产品化转译：

- 黑色背景转译为黑色文字和局部黑色焦点面板。
- 洋红光晕转译为页面中的“增长轨迹带”。
- 宣传册的大数字转译为可交互的主指标与变化解释。
- 大面积圆角卡片转译为少量有层级的双层容器。
- 静态品牌展示转译为任务、数据、原因和动作之间的连续关系。

## 3. 视觉方向

### 3.1 风格名称

**White Editorial Operations / 白色编辑式运营系统**

视觉关键词：

- 白底黑字
- 品牌洋红
- 编辑式排版
- 非对称网格
- 大数字叙事
- 清晰数据层级
- 局部高饱和
- 轻量物理反馈

整体感受应当是：干净、直接、有观点、具有品牌传播感，但仍然是一个高效率工作界面。

### 3.2 标志性视觉：Growth Ribbon 增长轨迹带

页面最有辨识度的元素是一条“增长轨迹带”。它不是背景装饰，而是承担信息状态：

- 在 Overview 中，它从主指标的起点穿过趋势图，落到变化原因和待办任务。
- 在伙伴页面中，它表示关系成熟度和收入贡献。
- 在活动页面中，它变成从 Draft 到 Live 的发布轨道。
- 在财务页面中，它表示余额到结算日的现金覆盖区间。
- 在系统页面中，它表示数据从连接、同步到可用的传递路径。

默认形态为细的洋红曲线或色块切片；只有核心区域使用大面积色彩。页面其余部分保持安静，避免品牌色泛滥。

## 4. 色彩系统

### 4.1 核心色板

| Token | 色值 | 用途 |
|---|---:|---|
| Paper White | `#FAFAF8` | 页面主背景，略带暖度，降低纯白刺眼感 |
| Surface White | `#FFFFFF` | 主要容器、侧边栏、抽屉 |
| Carbon Ink | `#111111` | 标题、核心数值、主导航 |
| Graphite | `#666366` | 正文、说明、次级信息 |
| Brand Magenta | `#F20A4F` | 主动作、选中态、增长轨迹、关键状态 |
| Coral Signal | `#FF6368` | 活动、提醒、趋势拐点 |
| Deep Wine | `#72062A` | 强调面板、图表深色端、悬浮态 |
| Mint Lift | `#C9F5D8` | 正向增长、健康状态、大数字渐变起点 |
| Data Blue | `#91B5FF` | 数据对比、次级系列、大数字渐变终点 |

### 4.2 使用比例

- 白色与近白背景：70%
- 黑色与灰色信息结构：22%
- 品牌洋红和珊瑚：6%
- 薄荷绿和数据蓝：2%

洋红仅用于“现在需要关注或执行的内容”。成功状态以薄荷绿表达，普通信息不使用彩色标签。

### 4.3 状态语义

- Active / Live：黑字 + 薄荷绿短线或圆点。
- Needs attention：洋红文字 + 淡洋红底，不使用红色描边框。
- Risk：深酒红文字 + 珊瑚色状态块。
- Scheduled：深酒红到洋红的渐变线。
- Draft：灰色斜纹或点阵，不使用灰色实心胶囊。
- Disabled：降低对比度并保留说明，不只依赖透明度。

## 5. 字体与数字

只使用项目 `fonts` 目录已有字体，避免后续演示依赖网络字体。

- 主字体：Plus Jakarta Sans。
- 中文回退：PingFang SC、Microsoft YaHei、sans-serif。
- 页面标题：800 字重，`clamp(34px, 4vw, 64px)`，字距 `-0.055em`。
- 模块标题：700 字重，24-32px。
- 正文：400 或 500 字重，13-15px，行高 1.65。
- 数据：700 或 800 字重，启用 tabular numbers，尽量避免数字跳动。
- 标签：700 字重，10-11px，字距 0.12em，仅业务域名称使用大写英文。

大数字不放在相同尺寸的小卡片里。主数字应像编辑标题一样承担构图重量，次级数字才进入列表或紧凑信息带。

## 6. 整体框架

### 6.1 桌面结构

```text
┌──────────────┬────────────────────────────────────────────────────────────┐
│ 品牌侧边栏   │ 页面身份 / 日期 / 搜索 / 通知 / 账户                       │
│ 232px        ├────────────────────────────────────────────────────────────┤
│              │                                                            │
│ Overview     │  非对称页面主舞台                                          │
│ Partners     │  页面标题、主数字、增长轨迹、工作区、右侧检查器             │
│ Campaigns    │                                                            │
│ Assets       │                                                            │
│ Rules        │                                                            │
│ Data         │                                                            │
│ Finance      │                                                            │
│ Messages     │                                                            │
│ Systems      │                                                            │
├──────────────┤                                                            │
│ Brand / User │                                                            │
└──────────────┴────────────────────────────────────────────────────────────┘
```

- 侧边栏固定宽度 232px，白底，与主页面只通过极浅色差和留白分隔。
- 主内容最大宽度 1540px，左右内边距 36-48px。
- 顶部不是传统深色导航条，而是 76px 高的上下文行。
- 页面首屏不堆卡片；先用一个强标题、一个主结论和一条增长轨迹建立阅读顺序。
- 右侧详情检查器在宽屏为 320-380px，可由列表项唤起；小屏改为底部抽屉。

### 6.2 侧边栏设计

- Logo 使用黑字与品牌洋红字标。
- 当前一级模块使用黑色文字、洋红竖线和浅玫红色背景切片。
- 子导航不全部长期展开，只展开当前业务域。
- 一级导航右侧只显示真正需要处理的数量，例如 Applications 12、Transactions 28。
- Badge 不使用传统圆角胶囊，改为右对齐的等宽数字和一条 12px 洋红短线。
- 底部保留品牌切换、用户身份和系统状态。
- 支持折叠为 72px 图标栏；折叠和展开由 CSS transform 驱动。

## 7. Overview 页面

### 7.1 页面结构

```text
┌──────────────────────────────┬──────────────────────┐
│ Good morning, Guowv          │ AUG 12 / US STORE    │
│ Revenue is moving faster     │ Systems 5/6 healthy │
│ than traffic.                │ Next payout Aug 16   │
├──────────────────────────────┴──────────────────────┤
│ $186,420.80  Gross sales      +15.2%                │
│ ───── Growth Ribbon / 主要趋势轨迹 ──────────────── │
├─────────────────────────────────────┬───────────────┤
│ 变化原因与趋势图                    │ Priority Stack│
│ 8 columns                           │ 4 columns     │
├─────────────────────────┬───────────┴───────────────┤
│ Partner performance     │ Campaign readiness       │
├─────────────────────────┴───────────────────────────┤
│ Risk strip / Quick actions                          │
└─────────────────────────────────────────────────────┘
```

### 7.2 关键模块

1. **Morning Thesis**：不是“Dashboard”标题，而是一句基于数据的业务结论，例如“Revenue is moving faster than traffic.”
2. **Hero Metric**：主数字与趋势线合并为一个编辑式横向区域，不再使用 8 张等尺寸 KPI 卡。
3. **Metric Rail**：Clicks、Orders、Commission、CVR 等次级指标排成一条可水平切换的细信息带。
4. **Why It Changed**：趋势图旁直接展示三条变化原因，点击原因可高亮对应时间段。
5. **Priority Stack**：任务像一叠待处理文件，按影响排序，最上层任务有洋红页签。
6. **Partner Spread**：伙伴采用排行与头像组合，悬停显示收入构成，点击打开详情检查器。
7. **Campaign Track**：活动以横向阶段轨道展示 Draft、Ready、Live、Settled，而不是普通表格。

## 8. 其他页面不使用同一种模板

所有页面共享侧栏、上下文行、字体和状态系统，但内容区采用四种不同页面骨架。

### 8.1 A 类：运营名册 Dossier

适用页面：

- Discover partners
- Applications
- My partners
- Invitation center
- Transactions
- Inbox
- Team & permissions

布局：左侧筛选与结果，中央是宽松记录列表，右侧是详情检查器。

特点：

- 列表不是传统密集表格，而是“档案条目”。
- 每条记录包含身份、关键指标、当前状态和一个主要动作。
- 点击条目后，右侧检查器以 shared-panel 方式展开，列表不跳页。
- 支持键盘上下选择条目，Enter 打开，Esc 关闭。
- 批量操作只在选中记录后出现，避免常驻工具条。

### 8.2 B 类：控制画布 Control Canvas

适用页面：

- All campaigns
- Affiliate programs
- Influencer campaigns
- Product feed
- Coupons
- Creative library
- Commission rules
- Attribution rules

布局：页面上方为阶段或状态轨道，下方是主要工作画布，右侧为属性检查器。

特点：

- Campaign 使用阶段泳道，不使用三列卡片。
- Product Feed 使用数据完整度地图，失败记录形成洋红缺口。
- Coupons 使用时间轴，明确显示上线、重叠和到期。
- Creative Library 使用不等宽媒体货架，图片和状态共同参与构图。
- Commission Rules 使用规则层叠视图，直观看到优先级和冲突。
- 点击节点后右侧更新属性，不打开新页面。
- 拖动只作为演示反馈，不改变真实数据；最终点击 Save changes 才显示完成状态。

### 8.3 C 类：分析账页 Analysis Ledger

适用页面：

- Performance
- Exports
- Finance
- Balance & payments
- Invoices

布局：大数字结论占据左上，趋势与解释位于右上，下方为账页式明细。

特点：

- 主指标是页面排版中心，不再被包进小卡片。
- 对比数据用细线、面积和数字差，不依赖彩色图例。
- 财务页面使用“余额到结算日”的资金轨迹带。
- 明细表采用账页式横线、强数字对齐和轻量行高亮。
- 点击图表区间可过滤下方记录，并在标题处显示当前时间范围。
- Export 进入生成状态后，按钮图标沿增长轨迹移动，完成后提供下载提示。

### 8.4 D 类：资源与系统矩阵 Resource Matrix

适用页面：

- Product & assets 总览
- Data & transactions 总览
- Communications 总览
- Systems & access 总览
- Integrations
- Notifications
- Email templates
- API & developer

布局：左侧为当前系统健康结论，右侧为不等宽资源矩阵，下方为事件日志。

特点：

- 每个模块不是相同卡片，而是根据重要性分配宽度。
- 正常状态只显示短线和文字；异常状态才出现浅洋红底。
- Integrations 用数据流节点表现来源、处理与落库状态。
- Notifications 用优先级和渠道矩阵，不使用普通消息列表。
- API 页面突出 token 生命周期、调用健康和最近事件。

## 9. 交互设计

### 9.1 页面切换

- 点击侧边栏后，Growth Ribbon 先收束到侧栏选中线，再从新页面标题处展开。
- 内容以 420-620ms 的错峰淡入完成，不做全屏转场。
- 页面滚动位置在模块切换后回到顶部。
- 动画曲线统一使用 `cubic-bezier(.32,.72,0,1)`。

### 9.2 列表与详情

- Hover：记录向右移动 2px，状态线延长，背景从透明变为 `rgba(242,10,79,.035)`。
- Click：右侧检查器展开，当前行进入锁定选中态。
- 关闭检查器：焦点返回原记录，保证键盘路径连续。
- 详情中的主按钮使用嵌套圆形箭头，按下缩放至 0.98。

### 9.3 图表与数据

- 图表默认只强调一个主系列，其他系列使用淡黑或数据蓝。
- Hover 数据点时，主数字随之更新，变化原因同步高亮。
- 日期范围切换采用线条重绘与数字滚动，不对整个卡片做闪烁加载。
- 表格排序时表头箭头旋转，行只改变位置与透明度。

### 9.4 筛选器

- 桌面端使用展开式筛选条，默认只显示 3 个高频条件。
- More filters 从标题下方展开，不弹出居中模态框。
- 已启用条件显示为“标签 + 值”，删除按钮只在 hover 或 focus 时出现。
- 移动端使用底部筛选抽屉，顶部固定 Apply filters 与 Clear。

### 9.5 快捷命令

- `Ctrl / Cmd + K` 打开全局命令面板。
- 支持跳转页面、搜索伙伴、搜索交易、创建活动、导出报表。
- 搜索结果按 Actions、Partners、Transactions、Pages 分组。
- 命令面板为白色浮层，背后只使用轻微遮罩，不使用大面积模糊。

## 10. 卡片与容器规范

只在重点区域使用双层容器，避免页面变成卡片墙。

- 外壳：`#F3F0F1`，padding 5-7px，圆角 24-30px。
- 内核：纯白或近白，圆角比外壳小 5-7px。
- 描边：使用 `rgba(17,17,17,.07)` 的内环，不使用普通灰色 1px border。
- 阴影：`0 24px 70px rgba(74,12,34,.07)`，只用于抽屉和重点卡片。
- 一般信息区优先使用留白、排版和细分隔线，不强制套卡片。

按钮：

- Primary：黑色或品牌洋红圆角按钮，文字清晰，右侧使用独立圆形箭头容器。
- Secondary：白底黑字，以浅内环区分，不使用灰底大胶囊。
- Destructive：只有真正删除或撤销资金操作才使用珊瑚红。
- Icon button：36-40px，精细线性 SVG 图标，保持 44px 最小触控区域。

## 11. 图表规范

- 主线：Brand Magenta。
- 对比线：Data Blue，透明度 55%。
- 正向面积：Mint Lift 到透明。
- 警戒区：Coral Signal 的 8% 透明色块。
- 坐标线：使用 `rgba(17,17,17,.07)` 点线。
- Tooltip：黑底白字，数字右对齐，圆角 10px。
- 图表说明必须用文字解释“为什么变化”，不能只有折线。
- 所有图表提供同等信息的可访问数据表入口。

## 12. 动效节奏

- 页面首入：标题先出现，Growth Ribbon 随后绘制，数据最后进入。
- 导航切换：总时长不超过 620ms。
- 抽屉：使用 transform + opacity，360ms。
- 图表：路径重绘 520ms，数字变化 420ms。
- Hover：160-220ms。
- 所有动效只操作 transform 与 opacity。
- `prefers-reduced-motion: reduce` 下取消路径绘制和错峰进入，仅保留即时状态变化。

## 13. 响应式策略

### 13.1 1200px 以下

- 右侧检查器改为覆盖式抽屉。
- Overview 的主趋势与任务栈改为上下排列。
- 主内容边距降至 24px。

### 13.2 768px 以下

- 侧边栏收进左侧抽屉，顶部保留品牌标志与菜单按钮。
- 页面标题降至 34-40px。
- 非对称网格回到单列。
- 大数字区保持横向可读，不将每个指标都变成一张卡片。
- 账页表格允许局部横向滚动，页面本身不得横向溢出。
- 所有悬停动作必须有点击替代。

## 14. 页面示例文案

避免使用泛化标题，如 Dashboard、Analytics Overview、Quick Insights。

推荐使用：

- Overview：`Revenue is moving faster than traffic.`
- Partner applications：`Four applicants can expand qualified reach this week.`
- Campaigns：`One approval stands between Summer Sale and launch.`
- Product feed：`Three catalog gaps are reducing partner coverage.`
- Transactions：`$8,420 in commission is waiting on review.`
- Balance：`Current funds cover six payout days.`
- Integrations：`Five of six data connections are healthy.`

标题负责给出结论，副标题负责解释上下文，按钮负责明确下一步动作。

## 15. Demo 展示状态

每类页面至少支持以下演示状态：

- Normal：完整示例数据。
- Empty：解释为什么为空，并给出首个行动。
- Loading：使用内容骨架，不使用整页旋转图标。
- Error：保留仍可用的数据，精确指出失败范围。
- Permission：显示可查看内容，禁用受限动作并说明需要的角色。
- Success：在原位置确认操作结果，不弹出无关庆祝动画。

## 17. 自检与取舍

本方案有意避免以下通用后台模式：

- 8 张完全相同的 KPI 卡片。
- 每个页面都复制“顶部指标 + 下方表格”。
- 大面积彩色渐变铺满白色后台。
- 随处使用胶囊标签、阴影和圆角卡片。
- 为了“科技感”加入玻璃模糊和发光球。
