# 完整功能目录

本目录是后续流程原型、高保真设计和研发拆分的共同输入。每一项都给出页面职责、信息、动作、状态和证据成熟度；没有证据的细节不会被写成已确认事实。

## 0. 阅读方式

- **页面 ID**：跨文档引用的稳定标识，后续路由名可以改变，ID 不随视觉方案改变。
- **优先级**：`P0` 核心闭环，`P1` 规模化运营，`P2` 扩展或待证明。
- **证据**：`C` 素材明确展示，`R` 仅入口/菜单可见，`P` 完整闭环建议。
- **通用要求**：每个列表默认包含搜索、筛选摘要、重置、分页/加载更多、无结果和失败重试；每个编辑动作包含校验、未保存提醒、成功反馈和权限拒绝。

## 1. 全局应用壳与总览

### GLO-01 全局应用壳

| 项目 | 内容 |
|---|---|
| 用户目标 | 随时知道当前品牌、账号、页面与系统待办，并可到达主要任务 |
| 必要信息 | 组织名、品牌/站点、账号与角色、当前语言、通知未读数、消息未读数、下载任务数、面包屑 |
| 主要动作 | 切换品牌/站点、切换语言、查看通知、打开信箱、查看下载、打开账号菜单、帮助、退出 |
| 必要状态 | 品牌仅一个/多个；无未读/有未读；下载排队/完成/失败；无权限页面；会话过期；维护通知 |
| 优先级 / 证据 | `P0 · C + P` |

**规则**

- 品牌切换会改变页面数据范围；切换前提示未保存内容。
- 页面标题和面包屑必须表达当前位置，所有详情与侧滑面板都有明确返回路径。
- 图标按钮必须有可见或辅助技术可读标签，不能只靠图形猜测。
- 全局日期、币种和时区需在数据页面保持可见或可查询。

### HOM-01 总览与待办

| 项目 | 内容 |
|---|---|
| 用户目标 | 进入系统后立即知道业务健康度和今天需要处理的事情 |
| 核心内容 | Total Sales、Paid/Estimated Commissions、Conversion Rate、今日销售/点击、活跃 Publisher、近期交易、Newsfeed/To Do、余额预警、同步失败与异常交易 |
| 主要动作 | 进入预设筛选后的对应工作队列；忽略/稍后提醒；切换品牌和时间范围 |
| 必要状态 | 新账号引导；无待办；部分数据延迟；集成未完成；权限受限的总览 |
| 优先级 / 证据 | `P0 · C + P`（基础指标和空状态已展示；行动化待办仍需定义） |

**不建议：** 只陈列孤立指标。每一张待办卡都应说明原因、影响和下一步。

## 3. 活动

### CAM-01 计划与活动列表

素材证明邀请时存在 `Affiliate Program` 与 `Influencer Campaign` 两类目标，也出现顶层 `Campaigns`，但没有活动管理页面。

**建议最低合同**

### CAM-02 活动工作区

建议以执行顺序组织：

1. Overview：目标、时间、负责人、状态与完成度

6. Performance：点击、订单、销售、佣金和内容结果

**必要状态：** 草稿、配置不完整、计划中、进行中、暂停、结束、归档；依赖缺失时说明缺什么并直达配置。

### AST-02 Amazon 商品筛选规则

**字段：** Storefront、Filter Type（White List / Black List）、ASIN 集合、同步状态、最近更新时间。

**规则：**

- 店铺必须属于当前品牌且 Amazon 授权在线。
- 画面说明 ASIN 以 B 开头、由 10 位字母数字组成；若未来支持非 B 开头的合法 ASIN，需明确兼容规则。
- 允许逗号、换行或回车分隔；按 Enter 触发逐项验证。
- 自动去重、去空白、统一大小写；无效项显示原因，不能静默保存。
- 保存前显示新增/移除数量；保存后进入待同步状态。
- 素材说明白名单和黑名单每天自动更新；同步成功后再更新产品库可推广范围。
- 白名单是手册推荐路径；黑名单虽存在，是否保留仍需业务确认。

`P0 · C`

**充值流程：**

1. 输入充值金额并校验最低/最高值与币种。
2. 确认总额；发生换汇时展示原币、结算币、汇率来源、费用和有效时间。
3. 选择账户余额、已保存银行卡、新银行卡、PayPal 或支付宝。
4. 新银行卡收集 Name on Card、Card Number、MM/YY、CVC，并可选择保存、设为默认和自动付款。
5. 支付宝标注仅支持个人账户；支付邮箱可与 YeahPromos 登录邮箱不同，提交后跳转第三方页面扫码或登录。
6. 第三方回跳和 webhook 需幂等；只有服务端确认后才更新余额与流水。

**动作：** Deposit、查看付款/订单详情、管理允许的支付方式、下载发票、分页；需要时导出（待确认）。

**必要状态：** draft、redirecting、pending、processing、succeeded、failed、cancelled、expired、refunded；余额不足；账单待支付/已支付/失败/退款；发票生成中/可下载/失败；无财务权限。

**安全：** 卡号/CVC 不进入 YeahPromos 日志或分析事件；充值、默认支付方式和自动付款属于敏感权限并记录审计。0 金额站点启用与真实充值使用不同文案和状态。

`P0 · C + P`

## 11. 所有页面必须实现的横切状态

| 类别 | 最低要求 |
|---|---|
| 加载 | 首次加载、局部刷新、长任务进度；避免用整页阻塞掩盖可用内容 |
| 空 | 新账号空、筛选无结果、权限不可见、数据尚未同步是四种不同空状态 |
| 错误 | 字段级校验、页面读取失败、提交失败、部分成功、第三方同步失败、可重试与支持信息 |
| 权限 | 隐藏不可发现的敏感入口；可见但不可操作时说明需要的角色和申请路径 |
| 并发 | 对象已被他人处理/更新时重新加载差异，避免静默覆盖 |
| 长任务 | CSV、同步、报告和发票进入任务中心，可离开页面后继续并收到通知 |
| 危险动作 | 删除、屏蔽、拒绝、作废、撤销集成需确认、原因、影响范围和审计记录 |
| 可访问性 | 键盘顺序、焦点、标签、错误关联、状态非仅颜色、图表表格替代、缩放与响应式重排 |
| 隐私安全 | 邮箱和付款信息按角色脱敏；凭证仅展示一次；公开仓库不得含真实客户或账号数据 |
