# 核心流程与分支

本文件描述站内对象如何跨栏目流动。视觉方案可以改变页面布局，但不得改变这些业务分支，除非先更新并重新确认框架。

## 1. 商家主闭环

```mermaid
flowchart LR
    A["发现或导入伙伴"] --> B["查看画像与匹配度"]
    B --> C["邀请加入计划/活动"]
    C --> D["伙伴接受或主动申请"]
    D --> E["商家审核与建立关系"]
    E --> F["配置商品、优惠券、素材与佣金"]
    F --> G["伙伴推广"]
    G --> H["点击、订单与佣金进入系统"]
    H --> I["商家复盘、审批/作废和导出"]
    I --> J["充值、付款与发票"]
    J --> K["优化伙伴、活动、商品和规则"]
    K --> A
```

### 入口

- 平台内搜索达人/媒体
- 对方主动申请
- 商家已知的站外联系人
- 活动内添加伙伴

### 闭环判定

至少完成“建立关系 → 可推广资产/规则齐备 → 有可追踪结果 → 可结算”，才算商家侧核心闭环。只完成“发现和发邀请”不是完整产品。

## 2. 平台内发现与邀请

```mermaid
flowchart TD
    A["选择达人或媒体"] --> B["搜索与筛选"]
    B --> C{“找到合适对象？”}
    C -- “否” --> D["调整或清空筛选"] --> B
    C -- “是” --> E["打开伙伴详情"]
    E --> F{“当前关系？”}
    F -- “合作中” --> G["消息、分组或加入活动"]
    F -- “已邀请” --> H["查看邀请状态或重发/撤回"]
    F -- “待审核” --> I["进入申请审核"]
    F -- “已屏蔽” --> J["仅有权限者可解除屏蔽"]
    F -- “未接触/已关注” --> K["邀请"]
    K --> L{“目标类型？”}
    L -- “联盟计划” --> M["选择计划"]
    L -- “达人活动” --> N["选择活动"]
    M --> O["选择渠道与模板"]
    N --> O
    O --> P["编辑并预览"]
    P --> Q{“校验通过？”}
    Q -- “否” --> P
    Q -- “是” --> R["发送"]
    R --> S{“发送结果”}
    S -- “全部成功” --> T["进入邀请中"]
    S -- “部分成功” --> U["逐收件人展示失败并重试"]
    S -- “失败” --> V["保留草稿并说明原因"]
```

### 必须确认的业务分支

- 同一伙伴是否允许同时加入多个联盟计划或达人活动。
- 已有未过期邀请时，系统是阻止、提醒还是允许覆盖。
- 邀请被拒绝后多久允许再次邀请。
- 商家关注是个人标记还是团队/品牌共享标记。
- 屏蔽的作用域是账号、品牌还是整个组织。

## 3. 站外联系人批量邀请

```mermaid
flowchart TD
    A["进入邀请中心"] --> B{“输入方式”}
    B -- “复制链接” --> C["复制品牌/计划专属邀请链接"] --> D["对方自行填写并加入"]
    B -- “手工输入” --> E["逐行填写姓名和邮箱"]
    B -- “CSV” --> F["下载模板并上传文件"]
    E --> G["格式、重复、已有账号检查"]
    F --> G
    G --> H{“检查结果”}
    H -- “已有平台账号” --> I["跳转平台画像或改用站内邀请"]
    H -- “字段错误/重复” --> J["按行修正或排除"]
    H -- “可邀请” --> K["选择计划、模板并预览"]
    K --> L["发送"]
    L --> M["显示每行结果并保存邀请历史"]
    D --> N["进入申请/加入流程"]
    M --> N
```

### 关键产品要求

- CSV 不是一次性黑箱上传；必须展示行级校验与部分成功。
- 真实姓名和邮箱属于敏感信息，上传历史按角色控制并支持保留期限。
- 系统邀请链接必须明确绑定的品牌、计划、佣金摘要、有效期和撤销方式。

## 4. 对方主动申请与人工审核

```mermaid
flowchart TD
    A["伙伴/渠道提交申请"] --> B["统一申请审核队列"]
    B --> C["打开画像与申请信息"]
    C --> D{“资料是否完整？”}
    D -- “否” --> E["请求补充信息"] --> F["等待申请人补充"] --> C
    D -- “是” --> G{“审核决定”}
    G -- “批准” --> H["选择渠道与佣金/分组"]
    H --> I{“自动批准此伙伴后续新渠道？”}
    I -- “是” --> J["保存伙伴级自动批准策略"]
    I -- “否” --> K["仅批准本次渠道"]
    J --> L["建立合作关系"]
    K --> L
    G -- “拒绝” --> M["选择原因并通知"] --> N["进入已拒绝，可按规则重新申请"]
```

### 并发与审计

- 审核页显示当前负责人或锁定状态。
- 若其他管理员已处理，提交前提示状态变化而不是覆盖。
- 保存申请来源、审核人、时间、决定、原因、渠道、规则与自动批准变更。

## 5. 商品与推广配置

```mermaid
flowchart TD
    A["连接店铺/商品源"] --> B{“同步成功？”}
    B -- “否” --> C["错误详情、重连或手工维护"] --> A
    B -- “是” --> D["商品 Feed"]
    D --> E["设置 Amazon ASIN 白名单"]
    E --> F{“ASIN 格式和店铺有效？”}
    F -- “否” --> E
    F -- “是” --> G["商品进入可推广范围"]
    G --> H["创建优惠券"]
    G --> I["上传文案/横幅"]
    G --> J["创建佣金规则"]
    H --> K["选择 Public 或 Private 伙伴范围"]
    J --> L["选择 ASIN/品类/伙伴/分组等条件"]
    K --> M["配置完整度检查"]
    I --> M
    L --> M
    M --> N{“是否存在缺失或规则冲突？”}
    N -- “是” --> O["展示问题和直达修复入口"] --> M
    N -- “否” --> P["可加入联盟计划或活动"]
```

### 规则边界

- 商品的“手工维护”和自动同步发生冲突时必须定义优先级。
- 优惠券平台有效期与 Amazon 实际有效期可能不同，界面必须提示而不能承诺一致。
- 私有优惠券未选择伙伴时不能发布。
- 佣金规则保存前应显示命中范围与冲突结果；不能依赖管理员猜测优先级。

## 6. 绩效分析到交易处理

```mermaid
flowchart TD
    A["选择品牌与日期范围"] --> B["选择指标与时间粒度"]
    B --> C["查看趋势"]
    C --> D["选择分组维度"]
    D --> E["查看明细表"]
    E --> F{“下钻对象”}
    F -- “品牌/伙伴” --> G["对象绩效视图"] --> E
    F -- “订单数/交易” --> H["交易明细"]
    H --> I{“是否需处理？”}
    I -- “正常” --> J["保留状态或导出"]
    I -- “批准” --> K["批量/单笔批准"]
    I -- “作废” --> L["选择原因并确认影响"]
    I -- “争议” --> M["进入交易申诉"]
    K --> N["更新佣金与审计记录"]
    L --> N
    M --> N
    E --> O["保存报告或导出"]
    O --> P["全局下载中心显示进度和结果"]
```

### 数据可信度要求

- 每个指标提供定义、币种、归因口径、数据源和刷新时间。
- Amazon BRB 的点击延迟等已知限制在视图内说明。
- 最后一天数据不完整时，不应画成“业绩突然下降”而不提示部分数据。
- 导出继承当前筛选、列和分组，并在导出任务中记录口径。

## 7. 财务与余额不足

```mermaid
flowchart TD
    A["系统估算待付佣金"] --> B{“余额是否充足？”}
    B -- “是” --> C["按规则产生付款/账单"]
    B -- “否” --> D["总览和财务页显示余额预警"]
    D --> E["选择充值金额与支付方式"]
    E --> F{“充值结果”}
    F -- “处理中” --> G["保留任务并通知结果"]
    F -- “失败” --> H["说明原因并允许重试/更换方式"]
    F -- “成功” --> I["更新余额和充值流水"]
    G --> I
    I --> C
    C --> J["查看付款详情"]
    J --> K["生成/下载发票"]
```

### 权限要求

- 只读财务角色可查看和下载，不可充值或改变支付方式。
- 充值金额、支付方式变更和退款应使用更高权限，并记录审计。
- 付款详情中的伙伴、订单和金额根据品牌范围过滤。

## 8. 团队账号与权限

```mermaid
flowchart TD
    A["创建/邀请团队账号"] --> B["填写姓名、邮箱和角色模板"]
    B --> C["选择品牌/站点范围"]
    C --> D["设置模块与动作例外权限"]
    D --> E["预览最终有效权限"]
    E --> F{“是否越权或缺少依赖？”}
    F -- “是” --> D
    F -- “否” --> G["发送邀请"]
    G --> H["用户设置密码/MFA"]
    H --> I["账号生效"]
    I --> J["记录登录与权限变更审计"]
```

### 关键原则

- 管理员不应为其他用户创建并查看明文密码。
- 角色模板解决大多数情况，权限树只处理例外。
- 多品牌权限是“品牌范围 × 模块动作”，不是两套互不相关设置。
- 删除账号前说明其报告、模板、活动和待办如何转移。

## 9. Amazon 商家入驻、授权与商品启用

~~~mermaid
flowchart TD
    A["设置 / 品牌管理"] --> B["新增唯一网站名称与 URL"]
    B --> C{“启用确认成功？”}
    C -- “否” --> B
    C -- “是” --> D["切换到新站点"]
    D --> E["完善品牌资料"]
    E --> F["配置项目参数"]
    F --> G["开始站点授权"]
    G --> H["选择 CPS/CPI、Website/App、Tracking"]
    H --> I["选择 Amazon 区域"]
    I --> J{“授权流程变体”}
    J -- “指南 + URL” --> K["授权访问、粘贴首页 URL 并验证"]
    J -- “Profile + Storefront” --> L["选择 Profile 与首页"]
    K --> M["测试订单/完成"]
    L --> M
    M --> N{“授权在线？”}
    N -- “否” --> O["保留进度、显示原因并重试"] --> G
    N -- “是” --> P["配置 ASIN 名单"]
    P --> Q{“格式有效？”}
    Q -- “否” --> P
    Q -- “是” --> R["保存并等待自动同步"]
    R --> S{“同步成功？”}
    S -- “否” --> T["错误、重试、通知"] --> R
    S -- “是” --> U["产品库显示可推广商品"]
    U --> V["充值并确认余额/流水"]
~~~

### 授权版本边界

- 中文新版展示 Amazon 集成指南、授权后粘贴店铺首页 URL 并验证。
- 英文旧版展示 Profile ID/国家/名称选择，以及 Storefront 首页选择。
- 两者是账号类型或产品版本分支，不能默认连续执行；当前生产逻辑需业务确认。
- 进度条中的“测试订单”“完成”只有阶段证据，详细字段与成功标准不得凭空补写。

### 商品来源边界

- Amazon 来源商品以自动同步为权威。
- 增减可推广商品通过 Amazon 筛选规则修改 ASIN；不要从产品列表直接新增、编辑或删除。
- 截图要求 ASIN 以 B 开头且为 10 位字母数字；支持逗号/换行/回车分隔并按 Enter 验证。若支持其他合法 ASIN，需另行定义兼容范围。
- 名单每天自动更新；保存规则后先进入待同步，成功后才改变产品库状态。
- 白名单是手册推荐路径；黑名单是否保留及冲突优先级需业务确认。

### 财务启用分支

- 0 金额站点启用与真实账户充值分开记录和表述。
- 充值支持素材中展示的已保存银行卡、新银行卡、PayPal 与个人支付宝；实际可用方式按地区/账号配置。
- 第三方支付回跳与服务端通知必须幂等；失败、取消、过期和汇率变化均可恢复且不重复入账。
- 完整页面合同、字段、状态与验收见 [Amazon 商家入驻、站点授权与商品启用](07-amazon-merchant-onboarding-and-products.md)。

## 10. 通用失败与恢复分支

所有 P0 流程至少验证：

1. 初次进入没有数据。
2. 筛选后没有结果。
3. 页面或局部数据加载失败。
4. 表单字段错误与提交失败。
5. 批量操作部分成功。
6. 第三方同步延迟或断开。
7. 用户无查看或操作权限。
8. 对象在提交前被另一用户修改。
9. 长任务在离开页面后继续，并可从通知/下载中心恢复。
10. 成功后对象状态、计数、列表和详情保持一致。
