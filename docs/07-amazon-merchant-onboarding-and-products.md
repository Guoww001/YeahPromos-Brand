# Amazon 商家入驻、站点授权与商品启用

> 补充证据：onboarding_images.zip 中 25 张图片（14 个页码，含同页多张截图）  
> 适用范围：Amazon 商家从创建品牌站点到商品可推广、账户可充值的站内闭环

## 1. 分析结论

这批素材补齐了原框架中证据不足的“品牌与站点”“项目设置”“Amazon 店铺授权”“商品来源控制”和“充值支付”五块能力。它们共同构成一条启用链路，而不是彼此独立的设置页面：

~~~mermaid
flowchart TD
    A["新增品牌/站点"] --> B["切换到目标站点"]
    B --> C["完善品牌资料"]
    C --> D["设置项目参数"]
    D --> E["完成 Amazon 站点授权"]
    E --> F["配置 ASIN 筛选规则"]
    F --> G["等待商品自动同步"]
    G --> H["检查产品库"]
    H --> I["充值并保持余额可用"]
    I --> J["站点具备推广准备条件"]
~~~

素材同时出现中文新版和英文旧版授权向导。两者的步骤名称、Amazon 授权方式和首页选择方式不完全一致，因此框架将其视为同一能力的两个流程变体，不能把所有画面机械串成一条固定路径。最终实现需由业务和集成团队确认当前生产版本。

## 2. 证据等级与边界

| 类型 | 处理 |
|---|---|
| 画面直接展示的字段、选项、动作和状态 | 标记为 C，进入框架基线 |
| 只在进度条出现但没有页面细节的“测试订单”“完成” | 标记为 R，仅保留阶段，不虚构字段 |
| 为保证可恢复、可审计而补充的错误与权限规则 | 标记为 P，需业务确认 |
| 图片中的账号、Profile ID、店铺 URL、卡号后四位、地址、二维码和金额示例 | 仅用于理解，不写入公开仓库 |

## 3. ONB-01 新增与切换品牌站点

### 入口与目标

- 入口：设置 → 品牌管理 → 品牌 → 添加集成。
- 用户目标：在同一组织账号下新增一个品牌/店铺站点，并切换到该站点继续配置。
- 新增后，头像菜单中的站点选择器可在多个站点之间切换；切换会改变全站数据范围。

### 表单合同

| 字段 | 要求 |
|---|---|
| 网站名称 | 必填；用于站点选择器与品牌卡片 |
| 网站网址 | 必填；需规范化协议、大小写、尾部斜杠后再做唯一性校验 |
| 价格 | 画面示例为 0.00，但不能硬编码为永久免费 |
| 订阅/账单说明 | 额外站点的订阅计划和账单周期自动跟随主账号 |
| 唯一性 | 额外集成账号的网站地址不能与主账号或其他站点相同 |

### 动作、状态与分支

- 添加：校验成功后创建站点；提交需幂等，避免重复点击产生多个站点。
- 付款：素材展示 0 金额确认付款；即使金额为 0，也要明确“无需扣款/确认启用”的结果。
- 切换站点：存在未保存内容时先提示；切换后所有列表、详情、设置、财务和下载任务均使用新站点范围。
- 必要状态：创建中、创建成功、网址重复、网址无效、付款确认中、创建失败可重试、无新增站点权限。
- 权限：默认仅 Organization Owner 或具备品牌管理权限的管理员可创建站点。

## 4. ONB-02 品牌资料完善

“账户详情”画面实际承载了品牌对外资料和推广规则摘要，至少包含：

| 区块 | 字段/能力 |
|---|---|
| 基础资料 | 店铺 Logo、品牌名称、品牌标识、网站网址、账户/订阅状态 |
| 品牌介绍 | ABOUT US 文本；素材中还出现可下载的商家激活指南附件 |
| 推广协议 | 面向伙伴的推广条款或协议正文 |
| 支持国家 | 一个或多个可运营国家/市场 |
| 关键词与类目 | 关键词标签、业务类目 |
| 联系方式 | 地址、城市及后续可能的联系人信息 |
| 元数据 | 最近更新时间、编辑入口、编辑人（建议） |

### 产品规则

- Logo 上传需限制格式、大小和比例，并提供上传中、失败、替换和预览。
- 品牌介绍、推广协议和附件需要版本、更新时间与发布状态，避免伙伴看到未完成草稿。
- 支持国家、类目和关键词影响伙伴发现、活动范围或合规时，保存前应显示影响摘要。
- 网站网址的修改可能使既有 Amazon 授权失效；保存前提示并要求重新验证。
- 公开给伙伴的内容与仅管理员可见的内部字段应分区。

## 5. ONB-03 项目参数与上线状态

### 已确认参数

| 参数 | 画面证据 | 框架要求 |
|---|---|---|
| 时区 | 示例出现 Pacific 与 New York | 站点级字段；影响报表、有效期和账单显示 |
| 货币 | 示例为 USD | 站点级字段；更改影响金额展示和规则解释 |
| 默认佣金 | 示例为百分比 | 必须说明单位、适用范围和被具体规则覆盖的优先级 |
| 确认周期 | 以天为单位 | 业务语义需确认；不能只存一个无解释数字 |
| Cookie 有效期 | 以天为单位 | 需显示归因含义和允许范围 |
| 自动批准权限 | 开/关 | 需说明批准对象、作用域、修改人和生效时间 |
| 站点授权 | 未设置/在线 | 进入 Amazon 授权向导；显示连接对象与状态 |
| 项目状态 | 线下/在线 | 授权与必要配置完成后进入在线；保留停用入口和影响说明 |
| 支付时间表 | 部分账号不可用 | 禁用时说明账号不适用并提供联系支持路径 |

### 配置完整度

站点上线不能只依赖一个手工开关。建议计算并展示：

- 品牌资料是否完成；
- 货币、时区、默认佣金、确认周期和 Cookie 有效期是否有效；
- Amazon 授权是否连接且未降级；
- 是否至少有一个有效商品筛选规则；
- 最近一次商品同步是否成功；
- 账户余额是否满足运营要求；
- 当前用户是否有发布权限。

## 6. ONB-04 Amazon 站点授权向导

### 6.1 共用阶段

素材中的进度条共同证明以下阶段：

1. Campaign Selection
2. Platform Selection
3. Tracking Selection
4. Tracking Installation
5. Homepage Selection 或 Test Order
6. Completion

其中“测试订单”和“完成”只有阶段名称，没有足够页面字段证据；保留阶段，但详细验收条件标记为待补。

### 6.2 选择项

| 阶段 | 已展示选项 |
|---|---|
| Campaign Selection | CPS、CPI |
| Platform Selection | Website、Mobile App |
| Tracking Selection | Shopify、Shoplazza、WooCommerce、Amazon、网站嵌入、API 连接 |
| Amazon Region | 北美洲 NA、欧洲 EU、远东 FE |

Amazon 商家手册的主路径明确选择 CPS、Website 和 Amazon，但其他选项仍是系统已展示能力，是否对 YeahPromos 首版开放需在权限和产品配置中控制。

### 6.3 授权变体 A：指南 + 首页 URL 验证

中文画面显示：

1. 选择 Amazon 区域。
2. 下载“亚马逊集成指南”并按说明向系统授予 Amazon 账户访问权限。
3. 从 Amazon 端复制店铺首页 URL。
4. 粘贴 URL 后点击“验证”。
5. 验证通过后才能进入下一步。

必要校验包括 URL 结构、市场与所选区域一致、店铺归属、重复绑定、授权过期和无访问权限。

### 6.4 授权变体 B：Profile + Storefront 选择

英文画面显示另一种集成方式：

1. 从授权返回的 Profile 列表选择目标记录；每项包含 Profile ID、国家代码和名称。
2. 从已发现的 Amazon Storefront/Homepage 列表选择首页；每项包含店铺名、页面 URL 和页面名。
3. 继续到 Completion。

这些字段可作为集成实体保存，但 Profile ID 和原始 URL 属于敏感业务标识，不应在日志、导出或公开证据中完整暴露。

### 6.5 统一数据合同

- integration_id、brand_id、storefront_id
- campaign_model、platform_type、tracking_provider
- amazon_region、marketplace_country
- external_profile_id（受保护）、profile_name
- homepage_url（按权限显示）、homepage_name
- authorization_status、verification_status、test_order_status
- connected_at、last_verified_at、last_synced_at、expires_at
- error_code、error_summary、recovery_action
- created_by、updated_by、audit_events

### 6.6 状态与恢复

建议状态：

- not_started
- configuring
- awaiting_authorization
- verifying
- connected
- test_pending
- online
- degraded
- authorization_expired
- disconnected
- failed

失败必须保留已完成选择，允许从失败步骤继续；断开或更换店铺前显示将受影响的商品、活动、规则、报表和归因数据。

## 7. AST-01 产品库

### 7.1 页面结构

- 入口：素材 → 产品库。
- 过滤：可用性、类目、品牌。
- 搜索：SKU、品牌、产品名称或类别。
- 辅助入口：Amazon 筛选规则、上传历史。
- 视图：列表/网格切换。
- 空状态：说明尚未添加商品，并提供添加产品或配置来源的下一步。
- 列表支持排序、分页和结果数。

### 7.2 列表字段

- SKU/ASIN
- 品牌
- 类别/产品名称
- 旧价/现价
- 可用性
- 最近更新
- 手动维护开关
- 操作：编辑、删除
- 建议补充：来源店铺、同步状态、失败原因、最后成功同步时间

### 7.3 Amazon 来源权威规则

素材同时展示“添加产品、编辑、删除、手动维护”控件，以及明确操作说明：

- Amazon 推广商品不应从产品库直接手工新增、修改或删除；
- 新增或删除 Amazon 商品应统一通过“Amazon 筛选规则”增减 ASIN；
- 直接手工维护可能影响正常推广。

因此框架定义为：

1. Amazon 自动同步商品以外部来源为权威，默认禁用直接编辑和删除。
2. 添加/移除进入可推广范围只修改筛选规则，不修改同步得到的产品实体。
3. “手动维护”仅可用于明确支持的非 Amazon 来源或紧急受控流程，并要求权限、原因、到期时间与审计。
4. 页面上出现的通用“添加产品”需要按来源解释；不能让 Amazon 商品进入错误路径。

## 8. AST-02 Amazon 商品筛选规则

### 表单合同

| 字段 | 要求 |
|---|---|
| 店铺 | 必须来自当前品牌已连接且在线的 Amazon Storefront |
| 筛选名单类型 | White List、Black List 均在画面出现 |
| ASIN 集合 | 标签化输入，逐项验证，显示有效与无效项 |
| 保存 | 保存前显示新增、移除和受影响商品数量 |

### ASIN 校验

- 画面说明 ASIN 以 B 开头、由 10 位字母数字组成；若未来支持非 B 开头的合法 ASIN，需明确兼容规则。
- 允许逗号、换行或回车分隔多个 ASIN。
- 输入后按 Enter 触发格式验证；无效项不能静默保存。
- 自动去重、去除首尾空白并统一大小写。
- 大批量输入需显示数量上限、处理进度、部分失败与可下载错误清单。

### 同步规则

- 画面说明白名单和黑名单每天自动更新。
- 保存筛选规则后进入 pending_sync，而不是立即承诺商品已可用。
- 同步完成后更新产品库数量、可用性和最近更新时间，并发送成功/失败通知。
- 白名单是当前手册的推荐路径；黑名单虽然存在，但是否保留是业务决定，不能仅凭红色操作说明永久删除。

## 9. FIN-01 充值、支付方式与流水

### 9.1 财务列表

- 账户余额、充值入口。
- 筛选：日期范围、付款方式、付款类型、状态、品牌、付款 ID。
- 字段：日期/时间、付款 ID、品牌、付款方式、付款类型、描述、金额、状态、操作。
- 空、处理中、失败、成功、退款和发票状态需分别表达。

### 9.2 充值步骤

1. 输入充值金额；画面以美元金额为输入示例。
2. 进入付款面板并确认总额。
3. 选择账户余额、已保存银行卡、新银行卡、PayPal 或支付宝。
4. 完成第三方支付后回到 YeahPromos，更新余额和付款流水。

### 9.3 新银行卡字段

- Name on Card
- Card Number
- MM/YY
- CVC
- 存储此付款方式
- 设为默认
- 自动付款开关

卡号和 CVC 不得由 YeahPromos 日志或分析事件采集；前端只使用支付服务商的合规组件与令牌。

### 9.4 支付宝与 PayPal

- 支付宝入口标注仅支持个人支付宝。
- 支付宝支付邮箱可与 YeahPromos 登录邮箱不同。
- 提交后会跳转到第三方页面，可通过扫码或登录个人账户完成。
- 若发生币种换算，确认页必须显示原币金额、结算币金额、汇率来源、费用和汇率有效时间。
- PayPal 作为独立支付方式展示，具体账号类型和币种范围待确认。

### 9.5 支付状态与安全

- draft、redirecting、pending、processing、succeeded、failed、cancelled、expired、refunded。
- 外部回跳和 webhook 必须幂等；不能仅凭浏览器回跳把余额记为成功。
- 充值、修改默认支付方式和自动付款属于 manage_sensitive 权限并进入审计。
- 0 金额站点启用与真实充值应使用不同文案和状态，避免用户误以为已充值。

## 10. 角色与权限补充

| 能力 | 建议默认角色 |
|---|---|
| 新增/切换品牌站点 | Organization Owner、Brand Admin（限授权范围） |
| 编辑公开品牌资料 | Brand Admin、Campaign Manager（可选） |
| 修改佣金、确认周期、Cookie | Organization Owner、Brand Admin |
| 发起/断开 Amazon 授权 | Brand Admin、Developer |
| 修改商品筛选规则 | Brand Admin、Campaign Manager |
| 查看同步错误 | Brand Admin、Developer、Analyst 只读 |
| 充值和支付方式 | Organization Owner、Finance |
| 查看付款流水/发票 | Finance、Organization Owner；其他角色按需只读 |

站点范围与动作权限同时生效。用户可以看见站点但无权修改时，页面需说明所需角色和申请路径。

## 11. 验收任务

### 成功路径

1. 新增唯一站点并完成 0 金额启用确认。
2. 切换到新站点，完善品牌资料与项目参数。
3. 选择 CPS、Website、Amazon 和目标区域，完成授权与首页验证。
4. 为已连接 Storefront 保存有效 ASIN 白名单。
5. 等待自动同步，产品库显示正确商品、价格、可用性和更新时间。
6. 输入充值金额并通过一种可用支付方式成功充值。
7. 返回财务页看到余额和流水更新，站点显示在线。

### 必测异常

- 重复或无效网站 URL；
- 授权被拒绝、过期或绑定到其他品牌；
- Amazon 区域与首页/国家不一致；
- Profile 或 Storefront 为空、重复或失效；
- ASIN 长度/字符错误、重复、部分有效；
- 保存规则后同步失败或延迟；
- 用户试图直接编辑 Amazon 来源商品；
- 充值金额无效、汇率过期、支付取消/失败、回跳重复；
- 无品牌、集成、商品或财务权限；
- 中途切换站点或离开页面后恢复进度。

## 12. 待业务确认

1. 当前生产授权流程采用“指南 + URL 验证”、Profile/Storefront 选择，还是按账号类型分流。
2. CPS、CPI、Website、Mobile App 与六种 Tracking Provider 哪些对首版开放。
3. Amazon 区域 NA/EU/FE 与实际 marketplace/country 的映射。
4. 测试订单的触发方式、成功标准、超时和是否可跳过。
5. 站点在线所需的最小配置和是否允许人工强制上线。
6. 确认周期的准确业务语义与可选范围。
7. 自动批准的对象、作用域、默认值与撤销影响。
8. ASIN 是否强制以 B 开头；若支持其他合法 Amazon ASIN，兼容范围如何定义。
9. Black List 是否保留；若保留，与 White List 冲突时的优先级。
10. 商品每日同步时间、时区、SLA、重试和手工立即同步能力。
11. 手动维护适用的商品来源和紧急授权流程。
12. 支持的充值币种、最低/最高金额、汇率与费用承担方。
13. 支付宝个人账户限制、PayPal 范围、银行卡自动付款和退款规则。
